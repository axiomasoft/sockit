# Правила слоёв

Правила слоёв Chatom (эталон, который SocKit повторяет для своих пакетов и обязан соблюдать как потребитель Chatom):

| # | Инвариант Chatom | Значение для SocKit |
|:--|:--|:--|
| L1 | Ядро не содержит ни одного `use` из namespace feature-пакета | packages/core SocKit не импортирует SocKit\Comments, мосты и модули по имени |
| L2 | Composer require ядра не содержит собственных feature-пакетов | packages/core/composer.json не требует sockit-forum/sockit-chatom |
| L3 | Feature-пакет достигает ядра только через публичную поверхность | условный SocKit adapter использует только #[Api]/#[Spi] владельца; модули SocKit — только публичные типы ядра SocKit |
| L4 | Ни один пакет не пишет в таблицы другого пакета | SocKit adapter не пишет в чужие Chatom/Forum таблицы, использует public owner API |
| L5 | Порядок core-стадий объявлен; пакеты не удаляют и не переставляют core-стадии | SocKit-стадии добавляются к именованным anchor; конверт SocKit (P2) так же защищён |
| L6 | Ядро бутится и проходит свои тесты без feature-пакетов | packages/core SocKit — отдельный CI job «core alone» |
| L7 | Потребитель не обязан знать внутреннюю структуру пакета | документация публичной поверхности |

Запрещённые формы связи (Chatom, применяются ко всем пакетам SocKit): импорт `\Internal\` чужого пакета; запись в чужие таблицы; cross-package FK, добавленный миграцией другого пакета (`ALTER TABLE` чужой таблицы); наследование от класса, не объявленного точкой расширения; чтение чужого config мимо его контракта. Исключение законно только при одновременном наличии ADR, decision record и явного allowlist в arch-тесте.
