# Тезисы SocKit

Тезисы меняются только новым решением. Действуют D14–D16.

| ID | Тезис | Как проверяется |
|:--|:--|:--|
| T-01 | **SocKit — panel-based social engine для любого Laravel-хоста: reactions/likes, posts/feed, optional groups и privacy. Комментарии и форум — Chatom/Forum; файлы — media owner; identity/tenancy/permissions — host.** | knowledge/panel-design; knowledge/requirements-trace |
| T-02 | **Ядро = механизмы, функции = модули.** В ядре только то, через что расширяются другие (surfaces, actor context, audience, modules, operation envelope, problems). Каждый элемент ядра имеет записанный deletion test; ответ «ничего не сломается у минимального потребителя» выносит его из ядра. | knowledge/architecture#deletion-tests, docs/architecture/core-boundary.md |
| T-03 | **Ядро не знает имён функциональных модулей. Глобальные modules.enabled ограничивают доступные модули; панель выбирает подмножество. Нет sibling imports; targets/capabilities соединяются через public registry.** | knowledge/panel-design; knowledge/requirements-trace |
| T-04 | **Один writer на каждую state identity** (B-01). Таблица state→writer — часть архитектуры; второй writer одной сущности — дефект. | knowledge/architecture#ownership, ownership-гейт (manifest `extra.sockit.owners`) |
| T-05 | **Чужие таблицы не читаются, не пишутся и не ALTER-ятся** (B-07, Chatom L4). Недостающие поля чужой сущности добавляются side-таблицей своей schema component/миграции с FK на чужой ключ. | arch-тест владения таблицами; review миграций |
| T-06 | **Зависимости только вниз.** packages/core не импортирует Chatom, Forum, AzGuard, Edufy, CoreX, ModKit, Vaulter. Пакет с чужим семейством — отдельный Composer-пакет; мост — `axiomasoft/sockit-<other>`, без бизнес-таблиц (B-03…B-06). | composer.json require-проверка + arch-тест namespace |
| T-07 | **Provider + builder + compile/freeze: отдельные PanelProvider/Panel и SurfaceProvider/Surface. Сначала collect во всех register(), затем compile/validate/freeze в booting после регистрации всех providers; early resolve и late mutation — явная ошибка.** | knowledge/panel-design; knowledge/requirements-trace |
| T-08 | **Регистрация только class-string и скаляры.** Config совместим с `config:cache`; closures в config запрещены; модуль не пишет в config ядра. | тест boot после config:cache; arch-тест на Closure в config |
| T-09 | **Публичная поверхность явна.** Контракты — `Contracts/`, `Data/`, `Enums/`, `Events/`, `Exceptions/` и классы с `#[Api]` (для потребителей) или `#[Spi(kind)]` (для реализаторов). Всё в `Internal\` — не контракт и меняется без SemVer. | arch-тест: публичный тип вне Internal имеет маркер; Internal не появляется в публичных сигнатурах |
| T-10 | **Fail-closed с причиной.** Ошибка адаптера, unknown, неизвестная версия схемы/события = deny/reject с problem code; никакой ошибки, превращённой в silent success. Решение объясняется (explain). | тесты unknown→deny; реестр problem codes |
| T-11 | **Типизированный валидный config; modules.enabled и modules.settings разделены, panels содержат только class-string. Ошибка указывает полный panel/module/key path.** | knowledge/panel-design; knowledge/requirements-trace |
| T-12 | **Ось замены существует только с swap-тестом.** Каждая заявленная ось (audience, contour, actor, safety, media, ranking, delivery) имеет fake и тест, подменяющий реализацию. | tests/Feature/Swap/* |
| T-13 | **Клиентские id не дают прав.** author_id, school_id, surface_id, group_id из payload не удостоверяют актора и контекст; ActorContext создаётся доверенным резолвером хоста (HTTP principal, trusted factory, worker re-resolve). | тесты spoofed actor (SN-02) |
| T-14 | **Аудитория — множество. Rank — только грубое ограничение категории публикации, никогда доказательство containment. Proposed audience должна входить в текущую surface boundary; неизвестное включение запрещено.** | knowledge/panel-design; knowledge/requirements-trace |
| T-15 | **Текущая проверка на каждом защищённом выходе:** PHP API, HTTP, worker, лента, поиск, media URL, уведомление, мост. Проекции/кеши/membership seats возвращают кандидатов, не право. | тесты revoke (SN-11) на всех путях |
| T-16 | **Хост — источник фактов, SocKit — механизм.** Identity, школы/классы/родители, consent, санкции, возрастные группы — у хоста; SocKit применяет их через SPI. | контракты SPI без school-моделей |
| T-17 | **Tenancy-neutral.** Tenant = изоляция хоста (соединение/БД/scope); `tenant_id` в доменных таблицах и DTO нет (B-10). | schema review, arch-тест на поле tenant_id |
| T-18 | **Идемпотентность: ключ + digest.** Тот же ключ и тот же digest → исходный результат после текущей авторизации; другой digest → conflict; ключ claim-ится в корневой транзакции мутации (B-09). | тесты SN-09 |
| T-19 | **Одна транзакция, сеть после commit.** Состояние + ревизия + receipt + outbox — одна транзакция на соединении владельца; внешний вызов только после commit; неизвестный исход = `unknown`, разрешается lookup по исходному ключу, не повтором с новым ключом (B-08). | fault-injection тесты SN-08 |
| T-20 | **CAS и tombstones.** Правка — по expected revision; удаление оставляет non-content tombstone с incarnation; устаревшее событие/репликация никогда не воскрешает удалённое. | тесты SN-14 |
| T-21 | **Проекции перестраиваемы.** У каждого денормализованного поля (счётчики, reply_count, stats) назван writer, rebuilder и поведение при удалении. | rebuilder-тесты |
| T-22 | **Комментарии вне SocKit domain: нет packages/comments, comments.* операций, comment body/tree/stats/seats/schema. Chatom Comments/Forum — owners; readiness fixture не доказывает production готовность.** | knowledge/panel-design; knowledge/requirements-trace |
| T-23 | **Интеграции с Chatom/Forum используют только подтверждённый public contract и включаются условно; отсутствие соседа не блокирует core/reactions/posts. Нет плана переноса comments из Sockit.** | knowledge/panel-design; knowledge/requirements-trace |
| T-24 | **Membership projection/seat/авторство не дают права доступа. Current actor + installation + panel/surface admission проверяются до audience, body/counters/media/cursor/receipt replay.** | knowledge/panel-design; knowledge/requirements-trace |
| T-25 | **Forum — зависимость, не мост.** Форумные функции SocKit строятся пакетом-модулем `axiomasoft/sockit-forum`, который требует Forum и использует только его публичный API (без повторения функциональности обсуждений); ядро `axiomasoft/sockit` от Forum не зависит; выделение Forum в отдельный репозиторий меняет только composer-ребро и compat-строку модуля. | D9; arch-тест модуля (нет `Chatom\Forum\…\Internal`) |
| T-26 | **Social reactions SocKit, message reactions Chatom и forum votes различаются по owner/state identity. Target adapter может разрешить социальную реакцию на внешнюю entity; автоматического зеркала реакций нет.** | knowledge/panel-design; knowledge/requirements-trace |
| T-27 | **Анонс в чат — проекция link-only**, не backend комментариев: `audience(channel) ⊆ audience(post)` текущей политикой, stable key, redact при сужении, ACK очереди ≠ доставлено. | тесты SN-17…SN-20 |
| T-28 | **HTTP/UI/SDK/admin — треки, не ядро.** Включаются при названном потребителе; SDK никогда не writer. | knowledge/architecture#tracks |
| T-29 | **Зелёное — только прошедшее.** Пропущенная/упавшая проверка не отмечается зелёной; fake driver и source observation не засчитываются как e2e. | правило плана |
| T-30 | **Внешние отчёты — доноры идей.** Рекомендации Perplexity и чужих платформ не имеют силы над каноном и не доказывают реализацию. | knowledge/perplexity-digest |
| T-31 | **Платность — доступность пакета, не ветка кода** (B-15): нет edition-флагов и pro-веток. | arch-тест на флаги edition |
| T-32 | **Панель — стабильная декларация поведения/storage с независимыми таблицами/моделями/настройками/модулями. Surface — entity instance внутри panel; tenant — контекст изоляции хоста. Одна entity может участвовать в двух панелях.** | knowledge/panel-design; knowledge/requirements-trace |
| T-33 | **Генерация consumer-owned provider/models/frozen migration snapshot: preflight всех файлов, отказ без overwrite, additive upgrade, deterministic identifiers. Снятие module/panel из config не удаляет данные.** | knowledge/panel-design; knowledge/requirements-trace |
| T-34 | **Frozen registry singleton не хранит actor/tenant/current panel. Явный immutable operation context; queue re-resolve и current authorization; A→B→A/exception/nesting изолированы.** | knowledge/panel-design; knowledge/requirements-trace |
